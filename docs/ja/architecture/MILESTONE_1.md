# マイルストーン 1 — イミュータブルなレビューパイプライン

[English](../../architecture/MILESTONE_1.md)

## ステータス

マイルストーン 1 では、Tier 1 の Git Artifact、ネットワークを使用しない構造検証、CRF-1 正規化、イミュータブルな Review Snapshot パイプラインを実装しています。承認と Git 書き込み操作は[マイルストーン 2](./MILESTONE_2.md)で実装されています。

## パイプライン

```text
READY 状態の Workspace
  -> クリーンでコミット済みの Git Bundle
  -> 信頼済みサーバー側での SHA-256
  -> コンテンツアドレス方式の成果物ディレクトリ
  -> ダイジェスト固定された Validator コンテナ
       network=none、読み取り専用ルート、上限付き tmpfs/リソース
       成果物ダイジェストのサブディレクトリだけを読み取り専用でマウント
  -> 構造化 Git マニフェスト（生のパスを正規 Base64 としてエンコード）
  -> 信頼済み CRF-1 正規化
  -> イミュータブルな Review Snapshot + レビューダイジェスト
```

Workspace が提供するのはバイト列であり、ID ではありません。`rad-control` は Bundle を信頼済みストレージへ移動する際に成果物ダイジェストを計算します。ストレージキーはそのダイジェストだけから導出され、既存のコンテンツアドレス方式のバイト列が置き換えられることはありません。

## Validator プロファイル

`RAD_VALIDATOR_IMAGE_DIGEST` が `RAD_VALIDATOR_IMAGE` から解決された Docker イメージ ID と完全に一致しない限り、検証はフェイルクローズします。その後、コンテナは可変タグではなく、そのイミュータブルな ID によって起動されます。

すべての Review Snapshot には、完全な Validator プロファイルとそのダイジェストが保存されます。

- イメージダイジェスト
- `/usr/bin/git` バイナリのダイジェスト
- CRF バージョン
- Canonicalizer のダイジェスト
- 構造ポリシーのダイジェスト
- Runner 設定のダイジェスト

Validator は Git を呼び出す前に成果物の SHA-256 を再計算します。一時的な Bare リポジトリ内で Bundle を検証し、ワークツリーは一切チェックアウトしません。

## CRF-1

CRF-1 は、再帰的にソートされたオブジェクトキー、安全な整数値、生の Git パスに対する正規 Base64、生バイト順でのパスの並びを使用します。パスの重複、未対応ステータス、不正なオブジェクト ID、非有限数、`undefined`、プレーンでないオブジェクトを拒否します。

レビューダイジェストは、Repository、Workspace、base/target/tree のオブジェクト ID、成果物と Validator プロファイルのダイジェスト、ポリシー、デプロイ Tier、セキュリティ Epoch、セキュリティ Posture Hash、構造化ファイルマニフェストを結び付けます。

セキュリティメタデータは検証の前後で取得されます。Posture または Epoch が変化した場合、結果は破棄されます。Snapshot の挿入と成果物の `VALIDATED` への遷移は、1つのデータベーストランザクション内で行われます。読み取り時は、データを返す前に両方の正規ダイジェストを再計算し、重複して格納された ID カラムを相互検証します。

## HTTP インターフェース

- `POST /api/workspaces/:id/artifacts` は、クリーンでコミット済みの Workspace を取得します。
- `GET /api/artifacts/:id` は成果物の ID と状態を返しますが、バイト列は返しません。
- `POST /api/artifacts/:id/validate` は Review Snapshot を作成するか、既存のものを返します。
- `GET /api/reviews/:id` は完全性を確認したイミュータブルな Snapshot を返します。

## 現在の制限事項

- 成果物の取得では Dirty な Workspace を拒否します。部分的または未コミットのレビューは意図的にサポートしていません。
- 既存の PostgreSQL ボリュームには、運用者が新しいマイグレーションを適用する必要があります。初期化スクリプトが自動実行されるのは新規ボリュームだけです。
- Validator イメージのビルドとダイジェスト固定は、それぞれ別の運用者向け手順です。
- 承認のバインディングと制御された GitHub 書き込みについては、マイルストーン 2 を参照してください。
