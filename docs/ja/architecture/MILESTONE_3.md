# マイルストーン 3 — 運用上のセキュリティ Posture

[English](../../architecture/MILESTONE_3.md)

## ステータス

マイルストーン 3 では、第4の垂直スライスと Tier 1 向け Security Gate D の自動チェックを実装しています。対象は、明示的な Posture マイグレーション、メンテナンスモード、追記専用の構造化監査、シークレットを含まない Transactional Outbox のプロトタイプ、レビューおよび運用上の可視性の拡張です。

## 起動およびマイグレーション境界

`rad-control` がセキュリティメタデータを初期化するのは、新規データベースの場合だけです。既存の Tier または Posture を暗黙に同期することはありません。差異がある場合は必ずスタンドアロンの管理コマンドを使用するため、通常のサーバー起動によって、保存済みの契約が弱められたり暗黙に置き換えられたりすることはありません。

マイグレーションでは、メンテナンスモードとロック済みのデータベーストランザクションを使用します。`PUSHING` は、リモート側の結果が曖昧な可能性があるため、必ず処理をブロックします。それ以外の場合、トランザクションはセキュリティ上重要な状態を無効化し、Epoch をちょうど1回だけ増加させます。失敗時はメンテナンスモードを維持し、Critical イベントを記録します。

## 監査

監査イベントには、データベースの ID シーケンス、Severity、Actor、Subject、Epoch、Tier、上限付きのフラットな詳細情報、発生時刻があります。アプリケーションの検証では、シークレットを示すキーを詳細情報に含めることを拒否します。PostgreSQL Trigger は Update と Delete を拒否するため、アプリケーションのデータベースロールから見てテーブルは追記専用です。

読み取り専用のステータスおよび監査 Endpoint は、次の場所で利用できます。

- `GET /api/security/status`
- `GET /api/audit-events?limit=50`

## Transactional Outbox

Workspace の Desired State の変更と Outbox への挿入は、同じトランザクション内で行われます。Command が持つのは Workspace ID と Desired State の意図だけです。Worker は `FOR UPDATE SKIP LOCKED` で Claim し、上限付き Backoff で再試行し、再起動後に古い Claim を回収して、既存の冪等な Reconciler へ配信します。状態の収束については、引き続き Reconciler が責任を持ちます。

## レビューの対象範囲

Review UI には、構造検証済みの全パスが、変更ステータス、変更前後の Mode、変更前後の Blob ID とともに表示されます。運用ヘッダーには現在の Tier、Epoch、メンテナンス状態が表示されます。監査タイムラインにより、ブラウザ側で管理操作を可能にすることなく、Posture の遷移を確認できます。

## デプロイ上の制限事項

- このバイナリが実装しているのは Tier 1 のコントロールだけです。
- 管理コマンドはホストまたは運用者向けのインターフェースです。Tier 1 UI には強力な管理者認証がないため、ブラウザ向けのマイグレーション Endpoint は公開していません。
- 既存のデータベースでは、このバイナリを起動する前にマイグレーション 007 から 009 を適用する必要があります。
- 監査の追記専用制御は Tier 1 の PostgreSQL 信頼境界を共有しており、データベース Superuser による操作は防止しません。
