# Milestone 0 — Workspace Vertical Slice

## Status

Milestone 0 is implemented as a runnable foundation, but is not declared
complete until the container build and an authenticated Codex task have been
verified in a deployment environment.

## Request flow

```text
Discord / Web
      |
      v
rad-control (Fastify modular monolith)
      |-- PostgreSQL: repository, workspace, task state
      |-- Reconciler: desired state -> observed state
      `-- Docker CLI: idempotent sandbox operations
                       |
                       v
                 Workspace container
                 |-- public repository clone
                 |-- code-server
                 `-- agent-worker -> Codex App Server
```

`rad-control` is the Tier 1 trusted computing base. Its internal modules are
logical architecture boundaries, not compromise-containment boundaries. The
Workspace container and its dedicated Docker network are enforced isolation
boundaries.

## State model

Workspace state uses independent `desired_state`, `observed_state`, and
monotonic `state_version` columns. Every update uses optimistic compare-and-set
semantics. The synchronous coordinator performs the first attempt; the
periodic reconciler repairs interrupted operations.

Sandbox operations are idempotent:

- create accepts an existing container and volume;
- start accepts a healthy running container;
- stop accepts an absent or stopped container;
- destroy accepts an absent container or volume.

## Codex App Server contract

The worker uses the protocol generated by Codex CLI `0.148.0`:

1. `initialize`
2. `initialized`
3. `thread/start`
4. `turn/start`
5. `turn/completed`

Threads use `approvalPolicy: never`, `sandbox: workspace-write`, a single
runtime workspace root, no external environment selection, and no multi-agent
mode. Unexpected server-to-client requests are denied.

The protocol remains experimental. The CLI version is fixed in the Workspace
image so an upgrade requires an explicit code and schema review.

## Current limitations

- Only public HTTPS Git repositories can be cloned.
- Workspace-scoped Codex identity provisioning is deployment-specific. The
  project intentionally does not mount a host `CODEX_HOME` or inject a reusable
  host API credential. Agent tasks fail closed until a deployment supplies a
  safe workspace-scoped identity mechanism.
- The IDE is mapped to host loopback with `--auth none`. It is suitable only
  for local Tier 1 deployment. One-time IDE URLs are Milestone 4 hardening.
- Database migrations are applied by PostgreSQL init scripts for a fresh
  volume. Upgrade migrations for existing installations are not implemented.
- Transactional outbox, artifact review, approval, and Git write are later
  milestones and are intentionally absent.
